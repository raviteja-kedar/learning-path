JavaScript Execution Model

Introduction to JavaScript Execution

JavaScript execution involves several key components that work together to run your code:

  • Call Stack: Tracks function calls in your code
  • Event Loop: Manages asynchronous operations
  • Callback Queue: Holds callbacks waiting to be executed
  • Web APIs: Provides functionality like timers, AJAX, and DOM manipulation

The Call Stack

The Call Stack is a data structure that tracks where we are in the execution of our code. It operates on the Last In, First Out (LIFO) principle. 

function firstFunction() {
  console.log("I'm the first function");
  secondFunction();
}

function secondFunction() {
  console.log("I'm the second function");
  thirdFunction();
}

function thirdFunction() {
  console.log("I'm the third function");
}

firstFunction();

Call Stack Execution:

  1. Call Stack begins empty
  2. firstFunction() is called and pushed onto the stack
  3. Inside firstFunction(), secondFunction() is called and pushed onto the stack
  4. Inside secondFunction(), thirdFunction() is called and pushed onto the stack
  5. thirdFunction() completes and is popped off the stack
  6. Execution returns to secondFunction(), which completes and is popped off
  7. Execution returns to firstFunction(), which completes and is popped off
  8. Call Stack is empty again

The Event Loop

JavaScript is single-threaded, meaning it can only execute one piece of code at a time. The Event Loop allows JavaScript to handle asynchronous operations without blocking the main thread. 

console.log("Start");

setTimeout(function() {
  console.log("Timeout callback executed");
}, 2000);

console.log("End");

Event Loop Execution:

  1. "Start" is logged to the console
  2. setTimeout() is registered with the Web API
  3. "End" is logged to the console
  4. After 2 seconds, the callback is moved to the Callback Queue
  5. The Event Loop checks if the Call Stack is empty
  6. If empty, the callback is moved to the Call Stack and executed
  7. "Timeout callback executed" is logged to the console

Asynchronous JavaScript

Asynchronous JavaScript allows operations to happen independently of the main program flow, enabling non-blocking behavior. Common asynchronous patterns include:

1. Callbacks

function fetchData(callback) {
  setTimeout(function() {
    callback("Data received");
  }, 2000);
}

fetchData(function(result) {
  console.log(result); // "Data received"
});

2. Promises

function fetchData() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve("Data received");
    }, 2000);
  });
}

fetchData()
  .then(result => console.log(result))
  .catch(error => console.error(error));

3. Async/Await

async function getData() {
  try {
    const result = await fetchData();
    console.log(result);
  } catch (error) {
    console.error(error);
  }
}

getData();

The JavaScript Runtime

The JavaScript runtime consists of several components:

  • JavaScript Engine: Executes JavaScript code (e.g., V8 in Chrome)
  • Web APIs: Provided by the browser (DOM, AJAX, setTimeout, etc.)
  • Callback Queue: Also known as the Task Queue
  • Microtask Queue: Higher priority than the Callback Queue (Promise callbacks)
  • Event Loop: Orchestrates the execution of tasks and microtasks
Note: Promise callbacks are placed in the Microtask Queue, which has priority over the Callback Queue. This means that all microtasks are processed before the next task from the Callback Queue.
