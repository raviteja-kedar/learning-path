JavaScript Engines

JavaScript engines are programs that execute JavaScript code. Different browsers use different engines:

V8

Used by Google Chrome and Node.js

SpiderMonkey

Used by Firefox

JavaScriptCore

Used by Safari

Chakra

Used by older versions of Microsoft Edge

How JavaScript Engines Work (Simplified)

Imagine a JavaScript engine as a factory that takes your written code (like a recipe), understands it, and turns it into actions your computer can perform. This process involves several steps and specialized workers (components).

How JavaScript Engines Work

JavaScript engines convert your human-readable code into machine code that the computer can actually understand and execute. This process involves several phases:

1

Compilation Phase (a.k.a. Creation Phase / Parsing Phase)

The engine parses your JavaScript code into an Abstract Syntax Tree (AST). JavaScript is not interpreted line-by-line anymore — it's Just-In-Time (JIT) compiled.

In this phase:

  • JS code is parsed into an Abstract Syntax Tree (AST).
  • Variables and function declarations are stored in memory (hoisting).
  • The scope chain is established.
  • No actual execution happens yet.
📌 Key things that happen:
  • Functions are fully hoisted (available entirely).
  • var is hoisted and initialized with undefined.
  • let and const are hoisted but remain in Temporal Dead Zone (TDZ).
// Hoisting Example
console.log(x); // undefined
var x = 10;

console.log(y); // ReferenceError
let y = 20;

// AST Example
function add(a, b) {
  return a + b;
}

// Becomes an AST (simplified version)
{
  type: "FunctionDeclaration",
  id: { type: "Identifier", name: "add" },
  params: [
    { type: "Identifier", name: "a" },
    { type: "Identifier", name: "b" }
  ],
  body: {
    type: "BlockStatement",
    body: [{
      type: "ReturnStatement",
      argument: {
        type: "BinaryExpression",
        operator: "+",
        left: { type: "Identifier", name: "a" },
        right: { type: "Identifier", name: "b" }
      }
    }]
  }
}
2

Memory Allocation Phase

Technically part of the compilation phase but worth separating mentally.

In this step:

  • JS engine allocates memory for all variables and functions.
  • Memory is reserved in the heap or stack, depending on the type.

🧠 Heap vs. Stack:

  • Stack: Primitive values (numbers, booleans, etc.)
  • Heap: Complex values (objects, arrays, functions)
3

Compilation & Optimization

Modern JavaScript engines use a combination of compilation and interpretation called Just-In-Time (JIT) compilation:

  • Interpreter: Quickly converts code to bytecode and executes it immediately
  • Compiler: Creates optimized machine code for frequently used parts
Key Point: V8's JIT compiler includes two components:
  • Ignition: A bytecode interpreter that generates and executes bytecode
  • TurboFan: An optimizing compiler that produces highly-optimized machine code

JavaScript engines continuously analyze code as it runs and apply various optimization techniques:

  • Hidden Classes: Track object shapes to optimize property access
  • Inline Caching: Remember where to find object properties
  • Function Inlining: Replace function calls with the function body
  • Dead Code Elimination: Remove unused code

Hidden Classes Example

// These objects have the same hidden class
const point1 = {x: 10, y: 20};
const point2 = {x: 15, y: 25};

// This creates a new hidden class
const point3 = {y: 30, x: 40}; // Different order
4

Execution Phase (a.k.a. Runtime Phase)

Now the code is actually run, line by line:

  • JS assigns values to variables.
  • Functions are invoked.
  • The call stack is used to track what's executing.
  • Closures are formed if needed.
  • The event loop, Web APIs, and queues start playing a role for async code.
function greet() {
  console.log('Hello');
}
greet(); // Execution happens here

// Call Stack Example:
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.log('Hello from third function!');
}

first();

// Call Stack Sequence:
// 1. first()
// 2. first() -> second()
// 3. first() -> second() -> third()
// 4. first() -> second() -> third() -> console.log()
// 5. first() -> second() -> third()
// 6. first() -> second()
// 7. first()
// 8. empty
This is also where:
  • Errors can be thrown
  • Promises are resolved/rejected
  • Async code gets deferred to queues
  • Scope resolution and closures take effect
5

Garbage Collection

JavaScript automatically manages memory through garbage collection, freeing up memory that's no longer needed.

Garbage Collection Process

  1. Mark: The engine marks all objects that are reachable from root objects
  2. Sweep: It clears memory occupied by unmarked (unreachable) objects
Tip: To optimize garbage collection:
  • Avoid creating unnecessary objects
  • Nullify references to large objects when no longer needed
  • Be cautious with closures that can create memory leaks
